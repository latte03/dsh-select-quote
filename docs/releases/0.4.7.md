# 0.4.7

修复 [#13](https://github.com/latte03/dsh-select-quote/issues/13)：流式回复里，批注指令后面的文字会「消失」，回复结束后才回来。

## 原因与做法

- 宿主每来一个 chunk 都会用 `nodeValue` 原地重写整段行内文字，而先前装饰器把那段文本节点拆走、换成自己的 chip 和文字。React 手里还是旧节点，后续 chunk 全写进已脱离文档的节点，可见内容就停在 chip 处。
- 现在改成**镜像切分**：宿主的文本节点留在文档里，只保留指令之前的前缀；chip 与其后的正文放进紧随其后的小容器，每次重写重新规划。正文不会再丢，流式期间就能看到 chip。
- chip 按批注序号复用，已经打开或悬停中的预览不会被重建打断；同一条回复里突然出现粗体、链接、行内代码时，阅读顺序也保持不变。

## 说明

- 旧的「行内代码」写法仍然兼容：这类形式等回复结束再换成 chip，因为宿主对 `code` 走的是整体 `textContent` 重写。
- 这套时序契约加进了真实 React + Chromium 的回归（`pnpm run verify:mirror`），覆盖流式逐 chunk、流式突发、行内标记生长、消息重渲染与模块热重载。
